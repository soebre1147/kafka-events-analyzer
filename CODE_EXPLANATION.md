# Как работает решение практических заданий 2 и 3

Вариант: Kafka-like события. Одна строка содержит четыре поля:

```text
orders 0 125 ORDER_CREATED
```

`orders` — тема событий, `0` — номер раздела, `125` — смещение события,
`ORDER_CREATED` — тип события. Анализируются текстовые строки этого формата.

## С чего начать читать код

1. `Main.java` создаёт фасад и вызывает его метод `run(args)`.
2. `KafkaAnalysisFacade.java` выбирает режим и вызывает остальные классы.
3. `CommandLineParser.java` проверяет параметры запуска.
4. `EventProcessor.java` читает строки из переданного входного потока.
   Фасад передаёт ему `System.in`.
5. `EventParser.java` проверяет одну строку и создаёт `KafkaEvent`.
6. `KafkaAnalyzer.java` запускает стратегии подсчёта.
7. `KafkaReportBuilder.java` собирает текст отчёта.
8. Классы из `storage` сохраняют результаты в файлы.

## Что находится в папках

`src/main/java` содержит исходный код Java. `org/example` — имя основного
пакета. `package` в начале файла показывает, к какому пакету относится класс,
а `import` позволяет использовать классы из других пакетов.

`model` — данные, которые программа хранит:

- `KafkaEvent` хранит одну правильную запись: topic, partition, offset и eventType.
- `EventType` содержит шесть разрешённых типов событий. Это `enum`.
- `InvalidLine` хранит номер неправильной строки, её текст и причину ошибки.
- `ParsedResult` хранит все правильные записи, ошибки и число прочитанных строк.

`cli` — параметры запуска:

- `CommandLineOptions` хранит выбранный режим и пути к выходным файлам.
- `CommandLineParser` читает массив `args`, проверяет обязательные параметры
  и возвращает `CommandLineOptions`. После `--json` и `--report` он читает
  следующий элемент массива и пропускает его при следующем проходе цикла.

`parser` — чтение и проверка входных событий:

- `EventParser` получает только одну строку. `split("\\s+")` разделяет её
  по пробелам или табуляции. `Integer.parseInt` превращает partition в число,
  `Long.parseLong` превращает offset в число. `EventType.valueOf` находит
  соответствующий тип события. При ошибке выбрасывается `ParseException`.
- `ParseException` — собственный класс ошибки формата строки.
- `EventProcessor` читает строки в цикле `while`. После успешного разбора
  добавляет событие в список. Если перехвачен `ParseException`, добавляет
  запись об ошибке в другой список и продолжает читать.

`analysis` — расчёты:

- `AnalysisStrategy` — интерфейс с методом `analyze`. Все стратегии реализуют его.
- `KafkaAnalyzer` создаёт список стратегий и по очереди запускает каждую.
- `AnalysisAccumulator` хранит изменяемые счётчики во время расчёта.
- `CountByTopicStrategy` считает события по теме.
- `CountByPartitionStrategy` считает события по номеру раздела.
- `CountByEventTypeStrategy` считает события по типу.
- `MaxOffsetByTopicStrategy` ищет максимальное смещение по теме.
- `MaxOffsetByPartitionStrategy` ищет максимальное смещение по номеру раздела.
- `CountPaymentEventsStrategy` считает PAYMENT_STARTED и PAYMENT_FAILED.
  ORDER_PAID в этом решении относится к событиям заказа.
- `KafkaAnalysisReport` хранит готовую статистику и список ошибок.
  Он реализует `Serializable`, чтобы его можно было сохранить в файл.

`report` содержит `KafkaReportBuilder`. Он получает уже готовую статистику
и добавляет строки отчёта в `StringBuilder`. Здесь нет подсчётов событий.

`storage` — сохранение и загрузка:

- `JsonResultWriter` собирает JSON с правильными событиями и ошибками.
  Метод `toJsonString` добавляет кавычки и заменяет специальные символы
  их JSON-представлением. Например, кавычка внутри текста записывается как `\"`.
- `JsonResultReader` читает JSON библиотекой Jackson. `ObjectMapper.readTree`
  разбирает файл, а `JsonNode.get` получает поле по имени. После проверок
  создаются объекты `KafkaEvent`, `InvalidLine` и `ParsedResult`.
- `JavaReportSerializer` сохраняет отчёт через `writeObject` и восстанавливает
  его через `readObject`. `try` с ресурсами автоматически закрывает файл.

`facade` содержит `KafkaAnalysisFacade`. Это общий порядок действий:
проверить параметры, прочитать и разобрать события, посчитать статистику,
сохранить файлы и вывести отчёт. В режиме просмотра он выбирает источник
по параметру. С `--report` загружается готовый бинарный отчёт. С `--json`
восстанавливаются сохранённые события и ошибки, а анализатор строит по ним
отчёт. Входные строки через `System.in` в этом режиме не читаются.

`target` содержит результат сборки: скомпилированные классы и JAR-файл.
`.idea` содержит настройки IntelliJ, включая три запуска. `pom.xml`
содержит настройки Maven, версию Java и зависимость Jackson для чтения JSON.
При сборке эта зависимость включается в готовый JAR.

## Конструкции Java, которые встречаются в коде

- Класс — описание данных и действий. Объект — конкретный экземпляр класса.
- `new KafkaEvent(...)` создаёт объект. Конструктор заполняет его поля.
- `String` хранит текст, `int` — целое число, `long` — целое число большего диапазона.
- `private` скрывает поле от прямого обращения из других классов.
- `final` у поля запрещает присвоить ему другое значение после инициализации.
- Getter, например `getTopic()`, возвращает значение поля.
- У `KafkaEvent` поля `private final` и нет setters, поэтому событие нельзя изменить.
- `List` хранит последовательность объектов. `add` добавляет объект в список.
- `Map` хранит пары «ключ — значение». `get` получает значение, `put` записывает его.
- `TreeMap` хранит ключи по порядку. `EnumMap` используется для ключей типа enum.
- `for` и `while` повторяют действия. `if` выбирает действие по условию.
- `try/catch` позволяет обработать ошибку и продолжить работу.
- `StringBuilder` постепенно собирает большой текст методом `append`.
- `Objects.requireNonNull` проверяет, что обязательное поле не равно `null`.
- `List.copyOf` делает неизменяемую копию списка. Обёртка
  `Collections.unmodifiableMap` запрещает менять карту через getter отчёта.
- `serialVersionUID` — номер версии сериализуемого класса.

## Пример одного подсчёта

В `AnalysisAccumulator.countTopic` сначала берётся старое число событий
для нужной темы. Если тема ещё не встречалась, старое число равно нулю.
Затем в карту записывается старое число плюс один.

При трёх событиях с темой orders карта постепенно получает значения
`orders: 1`, `orders: 2`, `orders: 3`.

В поиске максимума первое смещение записывается сразу. Каждое следующее
заменяет его только тогда, когда оно больше уже сохранённого значения.

## Что показать преподавателю

1. Выбрать в IntelliJ `Kafka — parse sample` и запустить.
2. Показать отчёт: всего 8 строк, 6 правильных и 2 ошибочных.
3. Объяснить ошибки: в строке 7 partition равен x, в строке 8 тип UNKNOWN
   отсутствует в enum.
4. Открыть `parsed-result.json`: там находятся события и описания ошибок.
5. Показать появившийся `report.ser`. Это бинарный объект отчёта.
6. Запустить `Kafka — show report`: он показывает отчёт из бинарного файла.
7. Запустить `Kafka — show JSON report`: он показывает такой же отчёт
   по сохранённым в JSON событиям и ошибкам.

Это учитывает устное уточнение преподавателя к третьему заданию:
`--show-report` должен работать с обоими форматами сериализованных данных.
При просмотре указывается либо `--json`, либо `--report`, оба сразу не нужны.

Если режим не указан, программа выводит сообщение об ошибке и подсказку.
Это проверка параметров, которая требуется в третьем задании.
